== ADR-0002: Idris2 Engineering Proof Kernel (Scope Clarified)

=== Status

Accepted, scope clarified (2026-11-01; original decision 2026-03-01)

=== Decision

Retain Idris2 for the repository's dependent AST, level predicates,
certificates, and engineering/interface obligations in the checked proof
corpus. This is a repository-specific tool choice, not a claim that Idris2 is
the estate-wide verifier for every proof class.

=== Policy alignment

Apply the current Standards proof mapping: Idris2 for engineering/API/ABI
contracts; Creusot for first-party Rust code; Agda as source for
implementation-independent theory, with rechecks in Rocq and Lean. Mathesis
Grade 3 denotes a locally checked Agda formulation, not an Idris2 build. The
separate `../../verification/proofs/AGDA-GRADE3-PORT-PLAN.adoc` records that proposed theory work.

Do not derive safety-level meanings from Idris2 features: canonical L3 is
`NullSafe`, L8 is `TemporalSafe`, and L9 is `LinearSafe`. The present L9
predicate checks an AST annotation; it is not a proof of runtime resource
linearity. QTT or erased proof terms do not establish source-parser correctness,
external proof transport, or a deployment property.

For current proof claims and residuals see
`../../verification/proofs/VERIFICATION-STANCE.adoc`; for the estate proof-grade
and verifier policy mapping see the
link:../audits/K-CUT-VCL-UT-RELATIONSHIP-2026-11-01.adoc[audit].

== ADR-0003: Historical Level Count and Taxonomy

=== Status

Superseded (2026-11-01; original decision 2026-03-16)

=== Record

This ADR captured a design proposal for ten levels numbered 1–10 and asserted
a one-to-one correspondence with TypeLL. Those statements are superseded and
must not be used as current implementation or cross-repository evidence.

The canonical code and wire tags are eleven levels, L0–L10:
`ParseSafe`, `SchemaBound`, `TypeCompat`, `NullSafe`, `InjectionProof`,
`ResultTyped`, `CardinalitySafe`, `EffectTracked`, `TemporalSafe`,
`LinearSafe`, and `EpistemicSafe`. The trusted Rust source parser reaches only
through L6. The L0–L10 Idris predicates and certificates apply to an already
constructed `Statement`.

No exact interface, source import, or theorem in this repository establishes
a one-to-one mapping to TypeLL or another repository's level numbering.
Shared ordinal numbers or similar names do not establish correspondence.
Use the canonical table in `ARCHITECTURE.adoc` and the
link:../audits/K-CUT-VCL-UT-RELATIONSHIP-2026-11-01.adoc[2026-11-01 audit].

== ADR-0004: Historical VCL-DT Supersession Proposal

=== Status

Superseded / scope withdrawn (2026-11-01; original decision 2026-03-16)

=== Record

The earlier claim that VCL-UT is a strict superset of VCL-DT, including the
claim that VCL-DT's six `PROOF` types are covered by VCL-UT L9–L10, is
withdrawn. The current canonical meanings are L9 `LinearSafe` and L10
`EpistemicSafe`; they are not `Proof Attachment` and `Cross-Cutting Invariants`.
The trusted Rust parser rejects `PROOF`, and no current source path establishes
automatic proof-type validation by L9–L10.

This record does not decide whether VCL-DT should be retired or how a future
migration should work. Any such relationship requires an explicit current
interface contract and proof/evidence mapping. See the current parser status
in `ROADMAP.adoc` and the
link:../audits/K-CUT-VCL-UT-RELATIONSHIP-2026-11-01.adoc[audit].

== ADR-0005: ReScript Parser Decision (Superseded)

=== Status

Superseded (2026-11-01; original decision 2026-03-01)

=== Record

The ReScript parser decision predates the trusted parser now used at the
VCL-UT boundary. The trusted, fail-closed source parser is the Rust crate
`src/interface/parse`; it produces the mirrored AST, wire representation,
and `vclt-gate` input. Its current source ceiling is L6. ReScript-side/editor
frontends, where present, are not the trusted parser unless their output
correspondence is separately established.

The Rust parser rejects the L7–L10 extension clauses and modal expressions;
closing that gap requires source syntax plus elaboration/binding and explicit
cross-frontend reconciliation. The earlier claims in this ADR about one
ReScript parser serving all deployment targets are design history, not a
current trust or deployment dependency. See `ROADMAP.adoc` and the
link:../audits/K-CUT-VCL-UT-RELATIONSHIP-2026-11-01.adoc[audit].

== ADR-0006: Epistemic Formalisation and L10 Scope

=== Status

Accepted; scope clarified (2026-11-01; original decision 2026-04-10)

=== Context

The canonical safety ladder has eleven tags, L0–L10. L10 is named
`EpistemicSafe`. The repository also contains epistemic type constructors and
an Idris2 Kripke-style S5 formalisation. These are distinct pieces of work:
the presence of the semantics module does not by itself show that L10's
source syntax or deployment path uses that model.

=== Decision

Retain L10 `EpistemicSafe` as a specified and proved predicate over the
`Statement` AST. Its current checker condition is structural: the statement
has an epistemic clause, declares at least one agent, references only declared
agents, and satisfies the implemented `ENTAILS`-cycle condition. The proof
certificate establishes that checker predicate, not a general semantic
warrant and not a deployment dependency on choreographic K-CUT.

`src/core/Epistemic.idr` separately formalises Kripke-style S5 frames,
accessibility properties, satisfaction and epistemic operators. It is included
in the proof package, but the L10 `Checker`/`Decide` path does not import or
invoke it. No local theorem connects that module to L10 certification, K-CUT,
or a deployment requirement. Preserve this separation unless an explicit
interface and proof establish a bridge.

=== Rationale

The distinction between knowledge-like and belief-like data remains a useful
design motivation. However, names and motivation are not evidence that the
current checker implements the complete S5 model, that its L10 result is
factive knowledge, or that a separate choreography system is required to
deploy VCL-UT.

The standalone model and the L10 structural predicate must be described at
their actual scopes. L10 source expressions are currently fail-closed in the
Rust parser, and the proposition carried by a programmatically constructed
L10 requirement is not yet schema-type-checked. See the parser/binder gap in
`ROADMAP.adoc` and the
link:../audits/K-CUT-VCL-UT-RELATIONSHIP-2026-11-01.adoc[2026-11-01 audit].

=== Consequences

- The standalone Kripke formalisation remains available as formal content; it
  is not represented as the runtime/deployment L10 model without a proved
  bridge.
- L10 is reported as a structural predicate over an existing `Statement`,
  not as proof that agents actually know or believe a proposition.
- The VCL parser does not yet expose the L7–L10 extension fields as source
  syntax; unsupported forms fail closed.
- K-CUT is not listed as a VCL-UT deployment blocker absent an explicit
  artefact establishing that relationship.
