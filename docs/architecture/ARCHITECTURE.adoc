== System Overview

VCL-UT is a dependently typed safety checker for VCL. Its canonical ladder has
eleven tags, L0–L10. The Idris proof predicates and dependent certificates
apply to already-constructed `Statement` values; the trusted Rust source parser
currently reaches only through L6 `CardinalitySafe`. The external gate does not
transport the Idris dependent certificate as a re-checkable proof object.

[WARNING]
====
This architecture document previously contained pipeline diagrams and
implementation descriptions that predated the canonical L0–L10 ladder and the
current parser / gate boundary. The sections below have been narrowed to the
implemented scope. Treat the level table and the 2026-11-01 audit as authoritative
for level names, proof scope, and source expressibility.
====

=== Implemented Pipeline Boundary

[source]
----
Runtime gate:
  VCL source -> Rust `parse_op` -> `VclOp`
    Query(Statement) -> `certified_level` -> query verdict
    Transit(Transition) -> `certified_transition_level` -> transition verdict (L4 ceiling)

Offline verification:
  Idris proof corpus checks corresponding predicates over the mirrored AST
----

The source parser is syntax-only and fail-closed on unsupported L7–L10
clauses. Schema resolution happens in the Rust decider for ordinary field
references. For `VclOp::Query`, `vclt-gate` calls the Rust
`certified_level` decider; `VclOp::Transit` is routed separately through
`certified_transition_level`, with an L4 ceiling and a transition-shaped
response. Neither runtime path invokes or links the Idris proof corpus. Idris
checks corresponding predicate and certificate claims offline over the mirrored
AST. The VeriSimDB consumer-side gate integration remains outstanding; this
repository does not establish a full parse-to-execution path.

== The 11 Safety Levels

The proof corpus defines eleven predicates and dependent certificates,
`ParseSafe` through `EpistemicSafe` (L0–L10), over the `Statement` AST. A
certificate at Level N includes the lower-level obligations; source
expressibility remains bounded by the parser's L6 ceiling.

=== Level Detail

The canonical level names and actual predicate scopes are listed in the table
above. Implementation anchors are `src/core/Levels.idr`,
`src/core/Decide.idr`, and `src/core/Checker.idr`; the source parser and its
fail-closed L7–L10 gap are in `src/interface/parse/src/parser.rs`. Do not use
the historical L1–L11 names or module mappings from earlier versions of this
architecture as a description of the current implementation.

== Cross-Project Relationship

Earlier versions of this document claimed a 1:1 mapping between VCL-UT levels
and TypeLL levels. That mapping is not established by the VCL-UT source or proof
corpus and is withdrawn here. Shared terminology, a level number, or a similar
type name is not an interface contract or a proof of dependency. Any
cross-project dependency must cite an explicit versioned artefact, import,
enforced build/deployment rule, or local theorem.

The same rule applies to choreographic K-CUT: no local artifact establishes it
as a VCL-UT deployment blocker. See
link:../audits/K-CUT-VCL-UT-RELATIONSHIP-2026-11-01.adoc[the relationship audit].

== Data Flow

The current implemented boundary is intentionally narrower than the historical
diagram that previously appeared here:

[source]
----
Runtime gate request (VCL source text)
  -> Rust `parse_op` (`src/interface/parse`) -> `VclOp`
       -> `Query(Statement)` -> `certified_level` -> query verdict
       -> `Transit(Transition)` -> `certified_transition_level` -> transition verdict (L4 ceiling)

Separately, the Idris proof corpus checks corresponding predicates over the
mirrored AST offline; it does not feed either runtime verdict. The versioned
wire codec is a separate interface and is not an intermediate step in this
`vclt-gate` request path.
----

The parser establishes syntax, not schema-bound types or a full certificate.
It rejects `PROOF`, `EFFECTS`, `AT`, `CONSUME`, `USAGE`, `EPISTEMIC`, and modal
expressions fail-closed. Consequently source reaches only through L6. The AST
and wire format contain extension fields, so constructed or wire-decoded
statements may carry L7–L10 data; that is distinct from source expressibility.
Ordinary field-reference resolution against `OctadSchema` occurs in the
decider.

The gate consumer is not yet wired into VeriSimDB. The Idris dependent
`SafetyCertificate` is not transported as a re-checkable proof object across
the external boundary; see `verification/proofs/VERIFICATION-STANCE.adoc` and
`docs/vclt-gate-contract.adoc` for the exact current contract.

== Gate Verdict and Proof Boundary

The Rust parser returns a typed `ParseError` and fails closed on unsupported
syntax. `vclt-gate` reports a schema-versioned JSON verdict with `requested_level`,
`certified_level`, per-level results, and reason categories; see
`docs/vclt-gate-contract.adoc` for the normative wire schema. A `certified_level`
tag is a verdict from the gate, not a serialized Idris proof object.

The Idris corpus contains dependent `SafetyCertificate` constructors and
soundness lemmas over `Statement`. That proof object is not transported across
the external boundary. Consumers must not treat the numeric level alone as a
re-checkable proof or as evidence of properties outside the corresponding local
predicate. See `verification/proofs/VERIFICATION-STANCE.adoc`.

== Certificate Scope

The term *certificate* is used for the dependent Idris value assembled by
`Checker.certifyAt` / `certifyRequested` inside the proof corpus. It does not
mean the current Rust gate emits a serialized dependent proof. Keep three
claims distinct: the predicates and certificates are specified/proved over an
AST; the source parser reaches only through L6; and no external deployment
dependency follows from those proofs without an explicit bridge artefact.
