# VCL-total ABI/FFI Documentation

## Overview

This library follows the **Hyperpolymath RSR Standard** for ABI and FFI design:

- **ABI (Application Binary Interface)** defined in **Idris2** with formal proofs
- **FFI (Foreign Function Interface)** implemented in **Zig** for C compatibility
- **Generated C headers** bridge Idris2 ABI to Zig FFI
- **Any language** can call through standard C ABI

## Why Idris2 for ABI?

### 1. **Formal Verification**

Idris2's dependent types allow proving properties about the ABI at compile-time:

```idris
-- Prove struct size is correct
public export
exampleStructSize : HasSize ExampleStruct 16

-- Prove field alignment is correct
public export
fieldAligned : Divides 8 (offsetOf ExampleStruct.field)

-- Prove ABI is platform-compatible
public export
abiCompatible : Compatible (ABI 1) (ABI 2)
```

### 2. **Type Safety**

Encode invariants that C/Zig cannot express:

```idris
-- Non-null pointer guaranteed at type level
data Handle : Type where
  MkHandle : (ptr : Bits64) -> {auto 0 nonNull : So (ptr /= 0)} -> Handle

-- Array with length proof
data Buffer : (n : Nat) -> Type where
  MkBuffer : Vect n Byte -> Buffer n
```

### 3. **Platform Abstraction**

Platform-specific types with compile-time selection:

```idris
CInt : Platform -> Type
CInt Linux = Bits32
CInt Windows = Bits32

CSize : Platform -> Type
CSize Linux = Bits64
CSize Windows = Bits64
```

### 4. **Safe Evolution**

Prove that new ABI versions are backward-compatible:

```idris
-- Compiler enforces compatibility
abiUpgrade : ABI 1 -> ABI 2
abiUpgrade old = MkABI2 {
  -- Must preserve all v1 fields
  v1_compat = old,
  -- Can add new fields
  new_features = defaults
}
```

## Why Zig for FFI?

### 1. **C ABI Compatibility**

Zig exports C-compatible functions naturally:

```zig
export fn library_function(param: i32) i32 {
    return param * 2;
}
```

### 2. **Memory Safety**

Compile-time safety without runtime overhead:

```zig
// Null check enforced at compile time
const handle = init() orelse return error.InitFailed;
defer free(handle);
```

### 3. **Cross-Compilation — NOT available for this shim**

Zig itself cross-compiles trivially, but `ffi/zig/build.zig` shells
`cargo build --release` with no `--target` and links the resulting **host**
staticlib (`libvcltotal_attest.a`) into every artefact. `-Dtarget=...` for a
different triple therefore fails at link time. Cross-target artefacts would
need the Rust backend built for the same triple (and that triple's std
installed) first; that is not wired up, so do not document or rely on it:

```bash
# Works (host):
cd ffi/zig && zig build

# Does NOT work today — links a foreign-architecture Rust staticlib:
# cd ffi/zig && zig build -Dtarget=aarch64-macos
```

### 4. **Zero Dependencies**

No runtime, no libc required (unless explicitly needed):

```zig
// Minimal binary size
pub const lib = @import("std");
// Only includes what you use
```

## Building

### Toolchain (do this first)

Three tools, and the Zig one is *pinned by this repository*:

| Tool | Needed for | Version |
|---|---|---|
| Zig | building/testing the shim | **0.16.0** (`.tool-versions`, `mise.toml`, `zig-shim-gate.yml`) |
| Rust / cargo | `build.zig` shells `cargo` to build `ffi/rust/attest` | stable |
| Idris2 | only the proof-corpus and ABI gates | 0.8.0 (built from pinned source in CI) |

Install the pinned Zig with the repo script — it reads the version out of
`.tool-versions`, so it cannot drift, and it verifies the download:

```bash
./scripts/install-toolchain.sh --check    # what is installed vs the pin
./scripts/install-toolchain.sh            # install it (into ~/.local/toolchains)
export PATH="$HOME/.local/toolchains/bin:$PATH"
```

It will not pipe a remote script into a shell. The default method downloads
the official tarball from `ziglang.org` and checks it against the SHA-256 in
`https://ziglang.org/download/index.json` before extracting; `--method pip`
uses the `ziglang` wheel where PyPI is reachable but `ziglang.org` is not;
`--from-file <tarball> --sha256 <digest>` handles air-gapped machines. If you
also use `mise`/`asdf`, `mise install` / `asdf install` read the same pins.

**There is no official Zig `curl … | sh` installer.** Any such line for Zig is
not from the Zig project. Nothing in this repository requires running one.

Rust has no pin here (`rust stable` in `.tool-versions`); use your distro's
rustup or the official `rustup-init`, verified against its published
checksum. Idris2 0.8.0 is built from a pinned source commit — copy the steps
from `.github/workflows/proof-corpus.yml` rather than trusting a package.

### Build FFI Library

```bash
cd ffi/zig
zig build                         # Build debug
zig build -Doptimize=ReleaseFast  # Build optimized
zig build test                    # Run tests
```

### C Header

The normative declarations are `ffi/zig/include/vclut_ffi.h`, installed to
`zig-out/include/` by `zig build`. It is hand-maintained and CI-checked
against the exports (`scripts/check-ffi-header.sh`: symbol presence + arity),
because the Zig shim — not the Idris2 ABI types — is what defines the
symbols. There is no `idris2 --cg c-header` step for this surface: the ABI
modules declare `%foreign` bindings, they do not emit C.

### Cross-Compile

Not supported by the current `build.zig` — it links a Rust staticlib built
for the host, so only the host triple links. See "Cross-Compilation — NOT
available for this shim" above.

## Usage

The full C contract is `ffi/zig/include/vclut_ffi.h`; these examples use the
real exported symbols. There is no `vcl_ut_*` API in this repository — an
earlier revision of this document invented one, and a consumer following it
would fail to link.

### From C

```c
#include "vclut_ffi.h"
#include <stdio.h>

int main(void) {
    uint8_t out[VCLUT_ATTESTATION_TOKEN_SIZE];
    const uint8_t sk[VCLUT_ED25519_SEED_SIZE] = { /* certifier seed */ 0 };

    if (vclut_init() != 0) return 1;

    int level = vclut_verify_wire(stmt, stmt_len, schema, schema_len,
                                  sk, sizeof sk, out, sizeof out);
    if (level < 0) {
        /* 0 is a VERIFIED level (ParseSafe) here, not "pending". */
        fprintf(stderr, "rejected: %s\n", vclut_last_error());
        return 1;
    }
    printf("certified level %d, %zu-byte token\n", level, sizeof out);
    return 0;
}
```

Compile with:
```bash
gcc -o example example.c -lvclut_ffi -L./zig-out/lib -I./zig-out/include
```

### From Idris2

```idris
import VclTotal.ABI.Tier2

main : IO ()
main = do
  case !(verifyWire stmtWire schemaWire certifierSeed) of
    Verified level token => putStrLn $ "certified level " ++ show level
    Rejected reason      => putStrLn $ "rejected: " ++ reason
```

`verifyWire` checks the seed width before calling, and reports the backend's
own message on a reject.

### From Rust

```rust
#[link(name = "vclut_ffi")]
extern "C" {
    fn vclut_init() -> std::ffi::c_int;
    fn vclut_verify_wire(
        stmt: *const u8, stmt_len: usize,
        schema: *const u8, schema_len: usize,
        sk: *const u8, sk_len: usize,
        out: *mut u8, out_cap: usize,
    ) -> std::ffi::c_int;
    fn vclut_last_error() -> *const std::ffi::c_char;
}
```

Other languages bind the same four symbols from the installed header.

## Contributing

When modifying the ABI/FFI:

1. **Update the ABI declarations first** (`src/interface/abi/*.idr`,
   package `vclut-abi.ipkg`)
   - Modify type definitions / `%foreign` signatures
   - Keep lengths `Bits64` (C `size_t`) and IDs `Bits64` (C `uint64_t`)
   - Typecheck it: `idris2 --build src/interface/abi/vclut-abi.ipkg`
     (CI: `abi-gate.yml`)

2. **Update the C declarations** (`ffi/zig/include/vclut_ffi.h`)
   - These are hand-maintained, not generated: the Zig shim defines the
     symbols, the Idris modules only name them
   - `./scripts/check-ffi-header.sh` must pass (CI: `zig-shim-gate.yml`)

3. **Update the FFI implementation** (`ffi/zig/src/lib.zig`)
   - Implement new functions; match the header's types and arity exactly
   - Run `cd ffi/zig && zig build test` (builds the Rust backend and links it)

4. **Add tests**
   - Unit tests in Zig
   - Integration tests
   - ABI verification tests

5. **Update documentation**
   - Function signatures
   - Usage examples
   - Migration guide (if breaking changes)
