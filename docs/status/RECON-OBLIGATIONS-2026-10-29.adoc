= VCL-UT reconnaissance: source-to-proof obligations and independent consumers

:sectnums:

Status: source-inspected 2026-10-29, BASE `main@ada2e7994632c35c9f46346acb41d84408fab4a0`.
This is an *obligation register*, NOT a claim that the complete architecture or
every proof has been independently reproduced. Runtime and formal builds must
be checked against pinned CI before upgrading any `REPORTED` status to
`REPRODUCED`. This document is independent of the Hypatia roadmap.

== As-built slices inspected

* The Rust source boundary is `src/interface/parse/src/{lexer,parser,ast,decider,wire}.rs`;
  `src/interface/parse/src/bin/vclt-gate.rs` is the JSON/exit-code front door.
  `parse_op` distinguishes relational `Query` from `Transit`; `parse`
  deliberately remains query-only.
* The Idris2 corpus `src/core/{Grammar,Schema,Decide,Levels,Checker,
  Composition,Epistemic,Transition}.idr` and
  `src/interface/{WireDecode,WireConformance}.idr` is built by
  `verification/proofs/vclut-core.ipkg`, gated by
  `.github/workflows/proof-corpus.yml` (Idris2 0.8.0 plus escape scan).
  Its Foreign/legacy Foreign modules are excluded from this package.
* `VCLW` (statement), `VCLS` (fixed octad schema), and `VCLT` (operation)
  are distinct versioned wire formats; the immutable tags are specified in
  `src/interface/parse/WIRE-FORMAT.adoc`. Cross-language correspondence is
  pinned on concrete golden vectors, not proved universally for arbitrary
  Rust byte strings.
* The principal runtime gate computes a Rust recomputation of predicates.
  It does NOT call Idris2 per request. The signed-attestation and wasm
  boundaries are separately described in the canonical
  `verification/proofs/VERIFICATION-STANCE.adoc`; the attestation and
  recomputation tiers must not be confused with a proof of real-world evidence.
* The top-level `vcl-total` Rust crate and the standalone
  `src/interface/parse` workspace are different build artefacts. The
  historical name is retained in crate, module and wire compatibility
  terminology. VCL-UT is the independent research/system identity.
* VeriSimDB's Elixir `VCLExecutor` and `VCLTGate` are distinct consumers.
  `VCLExecutor.gate_check` explicitly skips INSERT/UPDATE/DELETE; if
  a mutation lacks a proof, `execute_insert/update/delete` uses
  `{:ok, []}`. This is an *integration contract gap*, not a VCL-UT theorem.

== Safety level matrix

`Proved` here means proof of the *specified predicate* as reported in
the checked Idris2 corpus, NOT the colloquial force of a level's name.
`Source` records ordinary `parse_op` reachability. The Rust
`Statement`/wire data type can represent some fields that source cannot.

[cols="1,2,3,2,4",options="header"]
|===
|Level |Name |Rust predicate |Source |Meaning / limitation
|L0 |ParseSafe |Lex and parse |YES |Syntax only
|L1 |SchemaBound |Field references resolve |YES |Schema identity/authenticity external
|L2 |TypeCompat |WHERE comparisons compatible |INDIRECT |Unknown `TAny` permitted; HAVING and subquery scope need scrutiny
|L3 |NullSafe |Syntactic set of null guards |INDIRECT |Logical dominance/branch-sensitive safety not established
|L4 |InjectionProof |No string literal in WHERE |YES |Not arbitrary execution/injection freedom
|L5 |ResultTyped |SELECT items resolve beyond TAny |INDIRECT (through L6) |Not a universal runtime result type theorem
|L6 |CardinalitySafe |LIMIT is present |YES |No independent cardinality checking
|L7 |EffectTracked |Effect declaration present |NO |Parser rejects EFFECTS
|L8 |TemporalSafe |Version constraint present |NO |Parser rejects AT
|L9 |LinearSafe |UseOnce / Bounded annotation |NO |Parser rejects USAGE/CONSUME
|L10 |EpistemicSafe |Nonempty declared agents; direct 2-cycle exclusion |NO |Parser rejects EPISTEMIC/modal clauses; not knowledge veridicality
|===

The historical `docs/vcl-total-grammar.ebnf` has a different vocabulary
and larger expressive surface than the executable parser. The separate
VeriSimDB parser supports PROOF syntax not accepted by this gate.
L7–L10 may be reachable by constructing `Statement` values through
other interfaces; this is not evidence that ordinary source reaches them.

== Semantic contradictions / gaps to track

. `InjectionProof` names a narrow predicate, `!where_has_string_lit`.
  A raw string in HAVING is outside that check. Parameters are `TAny`
  for the recompute wire domain, so L2 comparison typing is weaker than
  resolved literal/parameter typing. Preserve the normative L4 predicate
  while designing a distinct, stronger safety condition; do not silently
  redefine L4.
. `NullSafe` is a set-of-guards test, not flow-sensitive dominance. In
  `GRAPH.x = NULL OR GRAPH.x > 0` the guard is collected globally.
  A preservation/safety theorem for this syntactic heuristic must not be
  assumed.
. `linearEnforced` and `epistemicConsistentStmt` certify limited shapes:
  a resource annotation and a direct two-cycle check are not resource
  accounting or general acyclicity, let alone real-world warrant.
. The normalisation syntax carries a `RepairJustification` tag but does
  not carry an authenticated proof that the selected modality is present
  or authoritative.
. The proof corpus is an intentionally narrow TCB model. No proof here
  establishes an authentic schema, clock, principal, physical witness,
  cryptographic primitive or correct side effects of the production store.
. Executable grammar, historical EBNF, Elixir/ReScript VCL and the wire
  AST are different language surfaces. Freeze compatibility effects and
  map each before extending syntax.

== Priority and independent consumer handover

P0 (engine and boundary): close bad schema metadata (VCL-UT PR #131),
make actual gate and parser semantics explicit, block missing-proof write
execution where policy requires proofs, and require authenticated
authorization/identity state checks before all mutations. Consumer changes
belong in VeriSimDB, not this language repo.

P1 (language and proof): separate predicate soundness from true execution
preservation; test HAVING, subquery, null-guard and unknown-type gaps;
add fail-closed source syntax for L7–L10 *only* with sound contextual
checking, not merely by parsing their existing AST variants.

P2 (cross-language / theorem reuse): establish checker correspondence beyond
golden fixtures, schema-binding and TOCTOU invariants, evidence
authentication, provenance descent, causal witness independence,
and Grade/session preservation. Consider ProofTransport and JanusKey as
first proof bridge experiments, with actual assumptions exposed.

P3 (maturity): incremental check caching keyed by versioned schema,
subject identity, operation, evidence hash and verifier version,
with revocation on any dependent change; measured performance and
per-consumer readiness classes.

The contract to a consumer is narrow: `admissible=true` attests successful
execution of the configured *static decision predicates on the supplied
syntax and schema*, not that a proposed state mutation is safe to commit.
An engine must independently authenticate principal and source data,
validate provenance and witnesses, enforce temporal/version and resource
constraints, and perform state transitions atomically. If any required
evidence is missing or a verifier is unavailable, fail closed.

This register must be updated per theorem with exact proof statement,
required premises, checker invocation and a reproducible CI receipt before
any item is promoted to fully verified production assurance.
