= VCL-UT L0–L10 Agda Grade 3 Port Plan
:revdate: 2026-11-01
:status: proposed, not proof evidence

== Purpose and status

Plan to formulate the current language-independent L0–L10 predicate and
certificate claims in Agda, targeting Mathesis **Grade 3** theorem-by-theorem.
This document is a work plan only: it contains no Agda proof, no CI receipt,
and grants no Grade 3 status. No `.agda` proof source is present in this
checkout, and the Agda compiler is unavailable in the current environment.

The current proof corpus is Idris2 engineering/formalisation evidence over the
repository's `Statement` AST. Under the Standards proof policy, repository
interfaces and engineering obligations stay in Idris2; first-party Rust code
belongs in the Creusot lane. Grade 3 is not a label for an Idris2 build: the
Mathesis architecture defines it as a locally type-checked Agda formulation
not yet translated to an independent foundational system. Do not replace or
downgrade existing Idris2 proof status by relabelling it.

Standards' canonical Agda entrypoint is:

[source,shell]
----
agda --safe --without-K --cubical-compatible <module.agda>
----

Pin and record the Agda and standard-library versions. The requested
installation target includes full Cubical Agda, separate from the estate
default profile; Creusot is to use its repository-pinned nightly alongside
latest stable Rust for VCL-UT. Full Cubical use in theorem source still needs
a separately reviewed proof profile with a theorem-specific rationale,
exact flags, and pinned versions. The current L0–L10 AST predicates do not by
themselves demonstrate a need for Cubical semantics. Failed or unavailable
tools leave the obligation open; flags must not be weakened to make a check
pass.

== Port inventory

The Agda theorem must preserve the *current proved predicate*, not strengthen
a safety-level name into a stronger semantic guarantee. The initial scope is
the Idris checker-acceptance implication and the dependent level/certificate
structure. Every row needs a side-by-side statement and assumption review
before implementation.

== Stages and gates

=== Stage 0 — Freeze the statement inventory

For each `checkLevelNSound`, level witness, certificate constructor,
`CanWeaken` rule, and composition-preservation lemma:

. copy its exact type and referenced predicate from the current Idris source;
. list all explicit and implicit premises, schema inputs, and universe/type
  assumptions;
. map every constructor and predicate to its Agda counterpart;
. mark unresolved or excluded behavior; and
. record the VCL-UT source commit and the source files reviewed.

Acceptance: a reviewer can compare Idris and Agda propositions line-by-line.
No theorem is represented by a matching name alone.

=== Stage 1 — Agda core model and L0–L1

Define the minimal statement/field/schema model needed for the first two
predicates. Keep the model independent of parser implementation details.
Prove the construction-level L0 fact and L1 field-resolution acceptance
implication. Pin the Agda toolchain/profile and run the real command in CI.

Acceptance: the proof and its assumptions type-check under the normative
profile; no `postulate`, unsafe option, or unreviewed foreign axiom discharges
the target theorem.

=== Stage 2 — L2–L5 typing, null, and injection predicates

Port the exact current comparison compatibility, null-guard, no-string-literal,
and selected-result predicates. Add acceptance-implies-predicate theorems for
each level. Port join-closure only where the current Idris theorem states it;
write separate counterexamples or explicit limitations for unproved stronger
claims.

Acceptance: positive and negative fixtures exercise each exact predicate, and
the Agda proposition is reviewed against the Idris source—not merely against
the level label.

=== Stage 3 — L6–L10 upper-level predicates

Port cardinality/effect/version presence, the enforced linear annotation, and
the structural epistemic predicate. For L10, prove finite transitive cycle
closure correctness and acceptance implies the specified structural
acyclicity. Keep proposition typing and Kripke semantics out of scope unless
separately formulated as additional theorems with explicit premises.

Acceptance: each predicate's intentional weakness is recorded; unsupported
source syntax remains a parser obligation and cannot be claimed as covered by
the Agda AST proof.

=== Stage 4 — Certificates, ordering, and composition

Port the dependent `SafetyCertificate` cases, `certifyAt` / `certifyRequested`
behavior, `CanWeaken` rules, and `compositionPreservation` obligations. Preserve
L10's non-join-closed cycle condition as an explicit side-condition; do not
weaken it to obtain a spurious unconditional composition result.

Acceptance: every certificate constructor is tied to its level predicate and
lower-level premises; every composition hypothesis appears in the Agda theorem
type. State separately what is not closed under composition.

=== Stage 5 — Grade 3 receipt and subsequent verification

For each theorem—not just for the package—retain: proposition, assumptions,
Agda source hash, VCL-UT source revision, Agda and library versions, exact
invocation, CI job/run URL, result, and reviewer comparison notes. Record a
Mathesis Grade 3 status only for the theorem with a successful local Agda
receipt and no missing assumption disclosure. Partial work remains theorem-
scoped; no umbrella Grade 3 claim for L0–L10 is allowed until every in-scope
row passes.

Grade 3 is the initial target, not the end of the Standards policy. Reconcile
theory statements with Rocq and Lean according to `PROOF-POLICY.adoc`; record
whether each leg was transported or re-proved and how proposition correspondence
was checked. Never infer cross-prover identity from filenames or theorem names.

== Separate engineering obligations

This Agda plan does not discharge these distinct obligations:

* Rust parser/decider implementation correctness: Rust verification lane
  (Creusot under the Standards policy), plus tests and explicit conformance
  evidence.
* Rust–Idris/Agda wire and predicate correspondence: exact schema/AST mapping,
  golden-vector evidence, and explicit refinement or conformance proofs.
* Parser source reachability: implement and bind L7–L10 syntax before claiming
  those levels are expressible from VCL source.
* Runtime schema, identity, evidence authenticity, clocks, resource behavior,
  database commits, and deployment integration: external assumptions and
  consumer-side evidence; not proved by AST theorems.
* Choreographic K-CUT dependency: no claim until a concrete interface,
  deployment rule, import, or theorem makes the dependency explicit.

== Current decision

**No Grade 3 claim is assigned by this plan.** The L0–L10 proof corpus remains
reported Idris2 evidence under `VERIFICATION-STANCE.adoc`; Rust source claims
remain in their implementation lane. The plan establishes how to begin an
Agda Grade 3 formulation and prevents that future work from being confused
with source expressibility, implementation correctness, or deployment
requirements.
